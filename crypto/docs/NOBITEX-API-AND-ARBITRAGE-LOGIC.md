# مرجع API نوبیتکس و منطق آربیتراژ پروژه

آخرین بازبینی: 2026-08-30

این سند خلاصه‌ی مستقل و پروژه‌محور مستندات رسمی نوبیتکس است؛ برای جزئیات تازه و تغییرات بعدی، مرجع نهایی همیشه [مستندات رسمی API نوبیتکس](https://apidocs.nobitex.ir/) است.

## هدف پروژه

داشبورد، قیمت و عمق بازارهای `RLS` و `USDT` نوبیتکس را نمایش می‌دهد و قیمت مؤثر اجرای معامله با سرمایه‌ی تعیین‌شده را با قیمت جهانی Binance مقایسه می‌کند. هدف، شناسایی فرصت بالقوه آربیتراژ در هر دو جهت است؛ این ابزار هزینه معامله، انتقال، برداشت، تأخیر، لغزش بازار مقصد و ریسک اجرا را فعلاً از سود نهایی کم نمی‌کند.

## واحدها و نام‌گذاری

- `1 تومان = 10 RLS`
- `1 MT = 1,000,000 تومان = 10,000,000 RLS`
- مقدار پیش‌فرض `100 MT = 1,000,000,000 RLS`
- نماد بازار ریالی API از پسوند `IRT` استفاده می‌کند، ولی کلید آمار بازار از `rls` استفاده می‌کند؛ مثال: `BTCIRT` در Order Book و `btc-rls` در Market Stats.
- `bestBuy`: بالاترین سفارش خرید موجود (Best Bid)، یعنی بهترین قیمت فوری برای فروش کاربر.
- `bestSell`: پایین‌ترین سفارش فروش موجود (Best Ask)، یعنی بهترین قیمت فوری برای خرید کاربر.
- `latest`: قیمت آخرین معامله.

## APIهای عمومی مورد استفاده

### آمار بازار

- متد و مسیر: `GET /market/stats`
- احراز هویت: ندارد
- محدودیت رسمی: 20 درخواست در دقیقه
- بدون پارامتر، همه بازارها را برمی‌گرداند.
- فیلترهای اختیاری: `srcCurrency` و `dstCurrency`؛ هرکدام می‌تواند مستقل ارسال شود.
- داده‌های مهم هر بازار: `isClosed`, `bestSell`, `bestBuy`, `volumeSrc`, `volumeDst`, `latest`, `mark`, `dayLow`, `dayHigh`, `dayOpen`, `dayClose`, `dayChange`.
- بخش قدیمی `global` منسوخ است و نباید منبع قیمت Binance باشد.

مرجع رسمی: [آمار بازار](https://apidocs.nobitex.ir/market_data/%D8%A2%D9%85%D8%A7%D8%B1-%D8%A8%D8%A7%D8%B2%D8%A7%D8%B1)

### دفتر سفارش نسخه 3

- متد و مسیر یک بازار: `GET /v3/orderbook/{SYMBOL}`
- مسیر تجمیعی همه بازارها: `GET /v3/orderbook/all`
- احراز هویت: ندارد
- محدودیت رسمی: 300 درخواست در دقیقه
- `asks`: سفارش‌های فروش، معمولاً از ارزان‌ترین به گران‌ترین.
- `bids`: سفارش‌های خرید، معمولاً از گران‌ترین به ارزان‌ترین.
- هر پله: `[price, amount]`؛ قیمت بر حسب ارز مقصد و مقدار بر حسب ارز مبدأ است.
- خروجی همچنین `lastTradePrice` و `lastUpdate` دارد.
- نسخه 2 Order Book منسوخ است و طبق مستندات قدیمی جای `asks` و `bids` آن با نسخه 3 تفاوت دارد؛ پروژه فقط باید از نسخه 3 استفاده کند.

مرجع رسمی: [دفتر سفارش نسخه 3](https://apidocs.nobitex.ir/market_data/%D8%AF%D8%B1%DB%8C%D8%A7%D9%81%D8%AA-%D8%AF%D9%81%D8%AA%D8%B1-%D8%B3%D9%81%D8%A7%D8%B1%D8%B4%D8%A7%D8%AA-%D9%86%D8%B3%D8%AE%D9%87-%DB%B3)

### تنظیمات سیستم و شبکه برداشت

- متد و مسیر: `GET /v2/options`
- احراز هویت و ورودی: ندارد
- شامل رمزارزها، شبکه‌ها، وضعیت برداشت، حداقل سفارش، دقت قیمت/مقدار، سقف برداشت و وضعیت فعال‌بودن دارایی‌ها است.
- پروژه از `networkList` و `withdrawEnable` برای نمایش و فیلتر شبکه‌های قابل برداشت استفاده می‌کند.
- فایل `data/nobitex-withdraw-networks.json` و دیتابیس داخلی، fallback زمان خطای API هستند.

مرجع رسمی: [تنظیمات سیستم](https://apidocs.nobitex.ir/options/get-system-options)

### قیمت جهانی

پروژه از API عمومی Binance Spot استفاده می‌کند. برای XMR که در Spot موجود نیست، قیمت Futures جایگزین می‌شود. داده‌ی `global` در پاسخ قدیمی نوبیتکس نباید استفاده شود، چون رسماً منسوخ شده است.

## فرمول دقیق Setup

فرض کنید `V` ارزش هدف معامله و هر پله Order Book شامل قیمت `pᵢ` و مقدار `qᵢ` باشد. پله‌ها به ترتیب بهترین قیمت مصرف می‌شوند. در آخرین پله فقط مقدار لازم برای رسیدن دقیق به `V` لحاظ می‌شود:

```text
remainingValue = V - accumulatedValue
usedAmountᵢ = min(qᵢ, remainingValue / pᵢ)
accumulatedValue += pᵢ × usedAmountᵢ
accumulatedAmount += usedAmountᵢ
VWAP = accumulatedValue / accumulatedAmount
```

اگر مجموع عمق دفتر سفارش برای پوشش `V` کافی نباشد، نتیجه `null`/`N/A` است؛ نمایش میانگین ناقص گمراه‌کننده خواهد بود.

### بازار RLS

- `RLS Buy Setup`: میانگین خرید کاربر از `asks` بازار رمزارز/ریال.
- `RLS Sell Setup`: میانگین فروش کاربر به `bids` بازار رمزارز/ریال.
- `USDT Buy Average`: میانگین خرید USDT از `asks` بازار `USDTIRT` برای همان ارزش RLS.
- `USDT Sell Average`: میانگین فروش USDT به `bids` بازار `USDTIRT` برای همان ارزش RLS.

دو نرخ ضمنی آربیتراژ:

```text
USDT Buy Setup = RLS Buy Setup / USDT Sell Average
USDT Sell Setup = RLS Sell Setup / USDT Buy Average
```

علت نرخ متقاطع:

- مسیر خرید رمزارز در نوبیتکس و فروش جهانی: ابتدا USDT روی bids فروخته و RLS تهیه می‌شود؛ پس مخرج، نرخ مؤثر فروش USDT است.
- مسیر خرید جهانی و فروش رمزارز در نوبیتکس: RLS حاصل باید روی asks به USDT تبدیل شود؛ پس مخرج، نرخ مؤثر خرید USDT است.

مقایسه با Binance:

```text
Buy opportunity %  = (Binance / USDT Buy Setup - 1) × 100
Sell opportunity % = (USDT Sell Setup / Binance - 1) × 100
```

عدد مثبت صرفاً Spread خام بالقوه است، نه سود قطعی.

### بازار USDT

- ارزش هدف USDT از تقسیم `Setup RLS Value` بر VWAP خرید تتر از `asks` بازار `USDTIRT` به دست می‌آید؛ در نتیجه عمق و لغزش تبدیل سرمایه نیز لحاظ می‌شود.
- `USDT Buy Setup`: VWAP روی `asks` بازار رمزارز/USDT.
- `USDT Sell Setup`: VWAP روی `bids` بازار رمزارز/USDT.
- مقایسه با Binance با همان دو فرمول بالا انجام می‌شود.

## محدودیت‌ها و نکات اجرایی

- Poll آمار هر 5 ثانیه برابر 12 درخواست در دقیقه و پایین‌تر از سقف رسمی 20 است.
- Order Book همه بازارها هر 5 ثانیه با یک درخواست تجمیعی دریافت می‌شود؛ این روش بسیار کم‌هزینه‌تر از درخواست جداگانه برای هر بازار است.
- پاسخ HTTP ناموفق باید قبل از JSON parsing خطا محسوب شود.
- محاسبات مالی با `Number` جاوااسکریپت انجام می‌شوند؛ برای اجرای سفارش واقعی بهتر است Decimal دقیق استفاده شود.
- کارمزد معامله نوبیتکس و Binance، کارمزد برداشت، شبکه مشترک، حداقل برداشت، زمان انتقال، Slippage بازار مقصد و امکان هم‌زمان اجراشدن دو سمت باید به سود خام اعمال شوند.
- برای داده لحظه‌ای‌تر می‌توان بعداً WebSocket رسمی را اضافه کرد: `public:orderbook-{SYMBOL}` و `public:market-stats-all`. توصیه رسمی این است که قبل از Subscription یک snapshot از REST v3 دریافت شود.

مراجع WebSocket: [معرفی](https://apidocs.nobitex.ir/websocket/%D9%88%D8%A8-%D8%B3%D9%88%DA%A9%D8%AA)، [کانال Order Book](https://apidocs.nobitex.ir/websocket/websocket-orderbook-channel)، [کانال وضعیت بازار](https://apidocs.nobitex.ir/websocket/websocket-market-stats-channel)

## نقشه کلی سایر بخش‌های API

مستندات رسمی علاوه بر داده بازار، بخش‌های اطلاعات کاربر، معاملات Spot، معاملات تعهدی، برداشت رمزارزی و ریالی، دفتر آدرس، امنیت، معرفی دوستان، احراز هویت، کلید API و سود و زیان را پوشش می‌دهد. این پروژه فقط از Endpointهای عمومی و بدون توکن استفاده می‌کند؛ افزودن API Key یا عملیات معامله/برداشت خارج از محدوده فعلی و نیازمند طراحی امنیتی جداگانه است.

## معیار صحت پروژه

1. `asks` فقط برای Buy Setup و `bids` فقط برای Sell Setup استفاده شوند.
2. آخرین پله به‌صورت partial fill محاسبه شود.
3. در صورت عمق ناکافی، مقدار نمایش داده نشود.
4. تبدیل RLS به USDT از نرخ متقاطع متناسب با مسیر آربیتراژ استفاده کند.
5. هیچ Endpoint منسوخ‌شده‌ای برای Order Book یا قیمت جهانی استفاده نشود.
6. تعداد درخواست‌ها زیر Rate Limit رسمی باقی بماند.
7. Spread خام از سود خالص تفکیک و صریحاً برچسب‌گذاری شود.
